# 原生 App（iOS / SwiftUI）的做法

> 这是我们家原生 iOS 客户端的实现思路。我们家 App 的源码不放出来。同文件夹的 [PovSnapExample.swift](PovSnapExample.swift) 是照同样思路另写的示范：一个只管左右的环境值、颜色和头像只看是谁发的气泡、用 ImageRenderer 离屏拍图、认出回复里的标记、按 match 挑消息。照着改进你自己的聊天界面就行。

## 核心：身份和位置是两个独立的属性

- 消息原来的 `role`（是用户发的还是 AI 发的）负责**身份样式**：气泡颜色、字色、头像、显示名、引用条的颜色。截图时不改。
- 新加一个环境值 `povReversed`，**只影响位置**：排版方向（靠左 / 靠右）、气泡尖角朝哪边、头像那一侧的边距。截图时设为 `true`。

这样就不需要复制一份主题实现。截图里的气泡颜色、字号、圆角、媒体卡片、用户自己设置的外观，全部自动跟当前设置一致。

## 渲染

- 截图时**复用聊天页现有的消息行视图**（我们家叫 `MessageRow`），挑出来的消息一条条放进去，离屏绘制，外层套上 `.environment(\.povReversed, true)`。
- 用 SwiftUI 的 `ImageRenderer` 把这段视图渲染成 PNG，宽度按手机屏宽，2x 或 3x。
- 渲染前先把图片、表情包预取下来，不然截出来是空白。动图表情包在截图里用静态图。
- 截图在聊天里显示成一张图片卡片，可以点开放大、保存到相册；同时在本机缓存一份，并上传服务器存一份（接口见 [../server/README.md](../server/README.md)）。

## 标记

- 解析消息时识别单独一行的 `<prism-snap .../>`，不显示原文。
- 一条 AI 回复如果只有标记、没别的字，这条消息仍然保留，用来放截图卡片。
- 选消息：支持 `last`、`match` + `context`（最近一处匹配，前后对称各带几条）。带标记的那条回复本身不进截图；一次最多 12 条。
- 我们家还实现过按消息编号截（`from` / `to`），但 AI 看到的编号和 App 本地的编号对不上，实际用不了，不推荐。

## 涉及的地方（按职责）

- 消息解析：识别并隐藏截图标记。
- 聊天页：选消息、离屏渲染、显示图片卡片、放大和保存、缓存和上传；启动时检查头像，服务器返回 404 才用本机头像补传。
- 消息视图：读 `povReversed`，只改位置、尖角、边距；颜色、头像、名字始终按原始 `role`。
- 网络层：新增用户本人头像上传、截图上传。

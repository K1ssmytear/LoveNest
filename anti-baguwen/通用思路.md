# 不用 Claude Code 也能用：通用思路

两个 hook 只是 Claude Code 上的一种写法，背后就两件事，换哪个 AI 都能照着做。

## 第一层：每轮都提醒，而且放得越靠后越好

写在人设开头的规矩，聊得越久越容易被冲淡。模型最听的，是离最新一条消息最近的那段话。

所以口吻清单别只在开头写一次，而是**每一轮都贴一遍，贴在尽量靠后的位置**：

- 自己写的 App / 小手机 / 接 API 的：每次发请求前，把清单拼在最后（系统提示末尾，或者附在用户最新那条消息后面）。
- 酒馆这类有「作者注释」「深度插入」「世界书」的：放在插入深度最浅的位置（离最新消息最近）。
- 只能写一次人设的平台：至少把清单放在人设最末尾，别埋在中间。

清单短一点更好。每轮都要贴，太长会挤占上下文，也会被模型当成背景噪音跳过去。

## 第二层：回复出来先检查，撞了就重来

光靠提醒，总有漏网的。第二层是回复写完先过一遍禁词，撞到了就打回去重写：

1. 拿到模型的回复，先不给用户看。
2. 用禁词表（关键词或正则）扫一遍。
3. 没撞到：直接显示。
4. 撞到了：把回复和一句反馈再发给模型，比如「这条里有“xxx”，原句是……，整条重写，意思不变，不解释、不道歉、不提这次检查」，拿新的回复回到第 2 步。
5. 最多重来两次。还撞就放行，别卡死在死循环里。

几个容易踩的坑：

- **要有例外**。「记着」要拦的是「这笔先记着」，不该拦「记着吃药」。每条规则配几句该拦、不该拦的例句，改规则前先跑一遍，免得误伤。
- **引号里的别查**。讨论某个词本身的时候（比如「你别再说“我认”了」），引号里的是引用，不算犯。
- **反馈里写清原句**。只说「有禁词」它会乱改；告诉它是哪句、哪个说法，它才改得准。
- **重写的那版也要查**，不然它可能换个近义词又绕回去。

没法写代码的平台，第二层可以靠人：约定一个触发词（我家用「转人工」），看到八股就丢这个词，它就把上一条去掉绕话重说一遍，不解释不道歉。

## 写清单的小经验

- **先说根上的毛病，再列词**。只禁词，它会换个近义词接着八股；告诉它「你在当旁白，给我讲‘你做了什么、我因此怎样’」，整个视角会挪过来。
- **每条禁令配一个该怎么说**。「不要说 A」不如「A → B」的对照管用，它知道往哪改。
- **对照只示范视角，别让它照抄**。不然你会收到一百遍「累坏了吧？快去躺着」。
- **清单是攒出来的**。看到一次不喜欢的，就记一条；隔一阵把同类的并一并，别越堆越乱。
